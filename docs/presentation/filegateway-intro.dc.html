FileGateway
분산 파일 서버 접근 게이트웨이

FileGateway는 분산 파일 서버에 이미 저장된 설비 로그와 Configuration File을 실제 서버 위치를 몰라도 조회·다운로드할 수 있게 하는 읽기 전용 게이트웨이다.

MVP 구현이 완료되어 통합 검증 단계를 거쳤으며, 배포 전 필수 확인 목록 통과만 남아 있다.

01 · BACKGROUND

배경 — 왜 게이트웨이가 필요한가

WPF 데스크톱, Web Backend/BFF, 다른 서버 시스템 등 여러 클라이언트가 설비별로 흩어진 분산 파일 서버의 로그·Configuration File을 조회해야 한다.

설비 직접 접속·로그 수집/가공·Configuration History 생성은 별도 시스템 책임이며 FileGateway 범위가 아니다 — FileGateway는 그 경계 위에서 읽기 전용 조회·다운로드만 담당한다.

02 · PROBLEMS

현재 문제점 — 클라이언트에 흩어진 파일 접근 지식

클라이언트가 파일 서버에 직접 접속하는 구조에서 반복되는 네 가지 부담이다.

2.1물리 경로·서버 지식 분산
클라이언트마다 설비별 서버 주소와 경로 규칙을 직접 보유해 변경에 대응하기 어렵다.
2.2FTP credential 다중 보유
클라이언트마다 FTP 계정을 각자 보관해 회전·감사 관리 부담이 크다.
2.3파일 종류별 탐색 규칙 상이
Hourly·Daily·Continuous 로그와 Configuration Current·History가 각각 다른 규칙을 가져 클라이언트마다 개별 구현이 필요하다.
2.4설비 추가 시 클라이언트 재배포
신규 설비·로그 종류가 늘 때마다 각 클라이언트 코드 변경과 배포가 뒤따른다.
03 · DIRECTION

개선 방향 — 논리 API로 물리 구조를 감춘다

클라이언트가 직접 FTP에 접속하던 구조를 걷어내고, equipmentId + 논리 조건만으로 호출하는 단일 진입점으로 재구성한다. AS-IS=slate/amber, TO-BE=indigo다.

05 · API

외부 API — HTTPS + JSON, X-Api-Key 인증

07 · OPERATIONS

운영 — 기준정보 캐시와 배포 시 유의점

코드 배포와 별개로 MSSQL 기준정보가 "어떤 설비가 어떤 서버·규칙으로 어떤 파일을 제공하는지"를 정의한다. refresh는 CacheTtl(기본 15분) 주기로 일어나며, 검증 실패는 전체 refresh를 거부하고 last-known-good을 유지한다.

7.1 기준정보 refresh

refresh는 FTP 서버 실재 여부를 확인하지 않는다 — 파일이 실제로 있는지는 목록/다운로드 시점에만 확인한다.

MSSQL SP 호출
↓ 구조 validation (rootPath 경계·cardinality)
검증
성공?
예 → cache 전체 atomic 교체
아니오 → 기존 cache 유지(stale)
7.2 인증·Secret

HTTPS + X-Api-Key header로 인증하며, FTP 계정·DB 연결 문자열 등 비밀은 환경변수로만 주입한다. 물리 경로·credential은 오류 응답과 로그에 남기지 않는다.

7.3 Health

/health/live는 생존만, /health/ready는 기준정보 상태를 반영한다. usable cache가 있으면 stale이어도 200을 반환한다.

WARN (주의)
IIS 배포 시 DataProtection:KeyDirectory가 App Pool 재시작 후에도 유지되는 경로여야 한다 — 유실 시 발급된 모든 fileId가 무효화된다. Application Pool의 "Load User Profile"도 함께 확인한다.
08 · SCOPE

범위 — 지금과 다음

MVP는 Windows Server + IIS 위 단일 Site·단일 프로토콜(FTP/FTPS) 구성을 다루며, 향후 Linux·다른 Site·다른 파일 Provider 확장을 허용하되 지금 선구현하지 않는다.

NOW (MVP)
로그·Configuration 조회·다운로드 API 호출가능
신규 설비·logType 자동 노출(DB 등록만)가능
실 운영 배포수동 검증 진행 중*
LATER
Linux 파일 서버 확장 · 다른 Site/credential 지원 · 다른 파일 Provider 추가 — 실제 요구가 확인될 때 IFileAccess 뒤에서 구현체만 추가한다.

용어

equipmentId — 클라이언트가 파일을 요청할 때 사용하는 설비 논리 식별자.
