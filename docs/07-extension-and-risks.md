# 확장성 및 주요 리스크

## 확장 방향

`Server Access Core`를 공통 기반으로 유지하고 파일 용도별 Provider를 추가한다.

예:

```text
FileGateway.Api
   |
   +-- LogProvider
   +-- ReportProvider       (future)
   +-- ConfigProvider       (future)
   +-- AdditionalFileProvider (future)
            |
      Server Access Core
```

새 Provider는 공통 파일 접근 기능을 재구현하지 않고 업무 규칙만 추가한다.

## 주요 리스크

### 1. 갱신 중인 파일 다운로드

계속 갱신되는 파일은 목록 조회 이후 크기나 내용이 변경될 수 있다. 다운로드 시점의 일관성 정책을 별도로 정해야 한다.

### 2. 대용량 파일

파일 전체를 메모리에 적재하지 않고 스트리밍해야 한다. 동시 다운로드 수와 네트워크 부하 제한도 필요하다.

### 3. 경로 보안

클라이언트 입력으로 실제 파일 경로를 직접 조합하면 Path Traversal 위험이 있다. 외부에는 논리 식별자만 노출하고 물리 경로는 서버가 기준정보를 통해 결정해야 한다.

### 4. 기준정보와 실제 파일 시스템 불일치

DB에는 경로가 있지만 서버/폴더가 없거나 반대 상황이 발생할 수 있다. 오류를 구분하고 운영 추적이 가능해야 한다.

### 5. 분산 서버 장애

특정 파일 서버 장애가 전체 FileGateway 장애로 확대되지 않도록 대상별 실패를 분리해야 한다.

### 6. 파일 목록 규모

기간이 길거나 파일 수가 많으면 목록 응답이 커질 수 있다. 향후 페이징/최대 조회기간 제한을 검토한다.

### 7. 권한

FileGateway 실행 계정이 여러 Windows 파일 서버에 접근해야 하므로 서비스 계정/공유 권한 정책이 핵심 운영 항목이다.

## 후속 결정 필요

- 인증/인가
- 서비스 계정 및 파일 공유 인증 방식
- 다운로드 재개(Range) 지원
- 파일 변경 중 다운로드 정책
- 최대 조회 기간 및 페이징
- 캐시 사용 여부
- 감사/접근 로그 정책
- 고가용성 구성
